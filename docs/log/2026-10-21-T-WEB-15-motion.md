## What was built

The owner asked for motion "to give the website a life". The site now moves in a calm, purposeful way, all in CSS:

- Arrival: the home hero and every inner page title settle in, one element after another (70 ms apart); the hero picture unveils; the quick actions panel rises in after the hero text.
- Scroll reveal: section headings, card lists, text blocks, the FAQ and the call-to-action panel rise into place as they scroll into view. Progress follows the scroll position (scroll-driven animations), so a fast scroll is never held up and content already in view is simply shown. Items in one row start slightly apart.
- Pointer: cards lift 3 px with the overlay shadow and a slow picture zoom; the department icon fills with teal; "view all" arrows nudge forward; quick-action icons rise. Hover effects need a real hover pointer, so taps on phones never leave a card stuck.
- Shell: the sticky header gains its shadow once the page scrolls; the departments dropdown and the hero search suggestions grow from their trigger; the mobile menu groups and FAQ answers open to their height; the phone bar slides up after the first paint.
- Booking: each wizard step rises in; the progress bar colors fade; the confirmation pops.
- Emergency: a soft repeating ring behind the emergency icon (hero line and emergency band), the only repeating motion on the site.
- Stats count up when they scroll into view, in the page digits (the stats section is hidden in the current content; an editor can turn it on).

Reduced motion removes all movement and keeps only short fades and color changes. Browsers without scroll-driven animations show sections in place.

## Decisions applied

- C-083: a public-site motion layer on top of ADR-022 section 13; nothing animates on keyboard-initiated actions.
- Entrances use fill-mode `backwards`, so a finished animation leaves no transform behind. A held transform makes a stacking context, which would put the hero search suggestions under the quick actions panel.
- Stat numbers are rendered final on the server and only count when they start below the fold, so a visible number never flashes to zero.
- Stat values now use the page digits (they showed Latin digits on Bangla pages).

## Known limitations

- Scroll reveals need scroll-driven animations (Chrome, Edge, Samsung Internet, recent Safari); elsewhere sections appear in place.
- Deploy impact: none.

## How to debug

- A section stays faint: it never fully entered the viewport; check that the list carries `reveal-list` only on a block-scrolling page (rows that scroll sideways on phones show in place by design).
- Something feels jumpy for a user: ask whether their system has reduced motion off; all movement is gated by `prefers-reduced-motion`.
- Search suggestions hidden under a panel: an animation is holding a transform; entrances must use `backwards` fill.
